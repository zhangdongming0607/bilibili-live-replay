# 历史实验记录与限制

以下是原项目保存的内部对比记录，整理时检查了相关方法文档与近期产物结构。**本次没有重新运行这组完整实验，也没有发布原始音频、转写和私人日志，数字不是可独立复现的公开榜单。**

同一场约 2 小时 45 分钟的歌回，以先前整理的歌曲轴作参照，参照含 34 个不同歌名，每种条件仅运行一次：

| 条件 | 记录中的参照歌名命中 | 记录中的认错/编造 | 约耗时 |
|---|---:|---:|---:|
| qwen-plus，一次性 + 云端转写 | 10/34 | 9 | <1 分钟 |
| GPT，一次性 + 云端转写 | 28/34 | 3 | 35 分钟 |
| GPT + 搜索 + 云端转写 | 32/34 | 0 | 12 分钟 |
| GPT，一次性 + Whisper 整场转写 | 31/34 | 0 | 26 分钟 |
| 完整 Agent：自主短窗重转、检索、迭代 | 34/34，另提出 3 首 | 0 | 21 分钟 |

记录中完整 Agent 重转了 130 个窗口、搜索 59 次，起点相对参照的绝对差中位数约 2 秒，另有 11 条被标待核对。模型准确版本、推理参数、设备与原始评分清单没有形成可公开复现的固定实验包，因此不能据此声称某个模型必然更好或“识别准确率 100%”。

参照本身也是模型生成；同源偏差、别名归并、只测一次、人工听审不足都会影响结果。额外条目也不天然是真阳性。原项目记录把这一结果用于选择端云架构，而不是作为商业效果承诺。

近期实际方法记录还包括：一场整场 20 个 Whisper 窗口、46 个短窗口、54 条导航，其中 4 条未确认；一次单曲任务发现解码样本时间与源媒体时间不同，做了局部相关性校准，但由于没有真正听到复核窗口，切点仍标 candidate。这些是流程证据，未转为用户听审通过。

要建立自己的评估集：选有授权的多场、跨语言材料；由独立人工先标歌曲身份与起止点；保存精确模型/提示词/版本；分开统计身份识别、漏检、误检、时间误差和听审通过率；对同一条件重复运行。比较脚本仅辅助对齐，不替代人工判断。
