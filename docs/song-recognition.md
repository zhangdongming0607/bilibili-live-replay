# 歌曲识别：方法与证据

## 不是把整场转写交给模型猜歌名

先用云端 Paraformer 得到廉价的文字线索，再让 Agent 根据空白区、语言变化、重复歌词和不确定条目决定是否做本地 Whisper 重转与检索。`mac/TASK.md` 是执行模板，`mac/REVISE.md` 接续人工修改，`mac/CLIP.md` 寻找单曲候选切点。

1. 把最终上传版本的音频作为时间基准，每个分 P 独立从零开始。保存源文件路径、大小、修改时间；重要交付可以额外算哈希。
2. 阅读云端逐字时间，先列候选歌曲和不确定区间。历史曲库只帮助检索，不作为“本场唱了”的证据。
3. 本地 Whisper 可按 600 秒分块、重叠 10 秒运行，保留每块缓存。使用低随机性、关闭前文条件，不向模型灌入预期歌名或歌词。
4. 自动语言识别会被音乐误导。主要中文场先用 zh，日语/英语片段单独用 ja/en 重转并对照，不用某种语言的低质结果覆盖全部。
5. 对起唱、尾句、串烧、口播、低声哼唱，用 20–90 秒窗口和逐词时间复核；ASR 时间只加一次窗口起点。
6. 用本场多句特征歌词检索发行资料/歌词来源，区分原唱、翻唱和同名曲。只报歌名、点歌、讨论歌名不算实际演唱。
7. 再唱、短哼和插话续唱按产品用途归并。简介导航通常保留首次起点，重复写备注；明显不同的完整演唱可以另列。
8. 休息/BGM 与主播演唱分开；ASR 的重复句、字幕署名、虚构词曲信息和纯音乐幻觉不能生成新条目。

## 时间戳有两种误差

**识别误差**：ASR 可能漏掉弱起、前奏和第一句；长句的句级时间不能直接作为每句歌词切点。

**媒体映射误差**：带时间戳回退的 OGG/OPUS 连续解码成 WAV 后，样本秒数可能与播放器源时间不同。实际记录出现过约 1 秒总时长差异，以及局部稳定偏移。不要把某一次测得的偏移常数搬到其他录播。

精剪时分别从源媒体取目标附近窗口，与连续 PCM 做互相关或检查 PTS，确认局部映射，再在最终视频播放器实际跳转。波形、频谱和互相关能帮助定位，不能代替听审对前奏、尾奏、聊天归属的判断。

拼接后的零点也会改变。无裁剪拼接为“前面片段实际时长之和 + 本段时间”，断流的墙上时钟缺口不能算进视频时间。调速、裁剪、转场后都要重新绑定。

## 导航与切片分别验收

- `verified`：歌曲身份有交叉证据，不代表人工已经听过，不代表帧级起点准确。
- `candidate`：只够提出候选；输出待核对。
- `uncertain` / `unknown`：保留缺口，不凑满歌单。
- `method.md`：记录真正运行过的窗口、语言、检索和局限；不能把“导出了音频窗口”写成“听过”。

切片以每次演唱为单位，前奏/尾奏要复听，首尾留白按实际内容决定。无法听音频时所有切点保持候选。`tools/clip.py` 只执行你已确认的数值区间，不替你验收听感。

## 复用和评估

`tools/catalog.py` 从自己确认过的 JSON/TXT 歌曲轴生成私人曲库。`tools/compare.py` 比较同一分 P 的歌名和起点；支持用 `--part` 选择分 P。匹配使用规范化名称和时间窗口，近似歌名可能误配，必须人工复核。参照也是机器结果时，召回/精确只是相对一致性。

没有附带真实歌词全文、音频或私人歌单。`examples/axis.json` 和离线 demo 使用虚构条目。历史实验的有限结果见 [evaluation.md](evaluation.md)。
