# 发布、分 P、切片与弹幕

## 一场录播的终点

1. biliup 自动投稿模板设置仅自己可见；上传字节完成不等于稿件已受理。
2. 云端检查、字幕初稿和歌曲轴排队；核对媒体已停止增长、探测结果、解码日志与已知缺口。
3. 给会话绑定正确 BVID，并核对每个分 P 的视频与本地文件一一对应。
4. 稿件审核通过后提交 CC 字幕；到播放器查看语言、位置和内容。SRT 是自动初稿，唱歌处可能错字很多。
5. 飞书核对歌曲轴，修改后重新确认；确认码只触发本版评论和置顶，不授权改变可见性。
6. 在创作中心编辑同一稿件，核对封面、转载来源、分区、标题、简介、分 P、字幕、歌曲轴和遮挡需求，确认后设置公开。
7. 分别记录“设置已提交”“审核/转码中”“登录账号可播放”“访客可播放”。只有实际访客检查后才认为公开播放验证完成。

公开状态修改目前是人工步骤；没有隐藏的自动转公开接口。需要集成 App 时，把这一人工闸口实现成明确的发布动作，不要让识别 Agent 持有投稿 Cookie。

## 分 P 与单文件

biliup 的 `file_size` / 录制分段配置决定原始分段；按所装版本管理页设置。平台单文件大小、时长限制会变化，不能把旧记录中的数值当固定规则。一场尽量一 P 可以简化导航，但较大文件要等更久才上传。

多 P 每个文件独立计时；评论中的 `2#01:02:03` 在原环境的桌面网页可跳 P2，手机端未得到一致效果。本程序输出该格式，实际可点性需要检查。长歌曲轴拆成多个主评论，楼中楼不作为时间导航。

多片段合并前比较编码、分辨率、音轨、采样率；规格兼容时用 FFmpeg concat，无损拼接仍需检查接缝重叠、时间戳、首尾损坏和完整解码。**重新合并、裁剪或重投后必须重做时间绑定与字幕，不能复用旧会话的完成状态。** 原始素材保持不变。

## 单曲切片

把 `mac/CLIP.md` 复制进新工作目录，替换歌名，提供当前录播音轨，并复制技能目录为 `skill/`。Agent 输出 `clip.json`、`method.md` 和候选窗口。先听前奏、尾奏及串话，确认这次演唱完整度，再执行：

```sh
python3 tools/clip.py --media /path/final.mp4 --start 120 --end 310 --output /path/song.mp4
```

默认重新编码，便于按确认的数值区间裁剪；可加 `--copy` 快速无损切，但可能受关键帧影响。脚本拒绝覆盖现有文件，生成后探测时长；仍需实际复听。上传单曲请创建正确标题/来源的独立私密稿件或明确的单曲分 P，不能把导航点到下一首之间的聊天当纯单曲。

## 弹幕与遮挡

上游 biliup 有[录后弹幕合成与本地素材工作流](https://biliup.github.io/biliup/docs/tutorials/post-recording-render/)。先确保录制保存了弹幕 XML 和视频，按照其界面合成、预览。与 CC 字幕属于不同层：CC 可以开关，烧进画面的字幕/弹幕不能单独关闭。

本仓库未实现缺失弹幕的事后补抓，也没宣称支持任何直播平台的历史弹幕恢复。照片/人脸/私密内容遮挡须对最终视频逐段核对；FFmpeg 解码通过证明不了遮挡完整。

## 首次正式使用的核对范围

新配置先跑一个短片，核对完整素材顺序、BVID/CID、私密范围、字幕提交与显示、歌曲轴修改、一次性评论、最终公开设置。所有线上写操作都使用自己的授权账号；本仓库离线测试不会操作账号。
