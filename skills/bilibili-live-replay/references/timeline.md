# 视频对应的歌曲时间轴

## 一条时间轴必须绑定一个最终视频

使用实际准备上传的文件作为零点。`axis.py init` 把路径、文件大小、mtime、ffprobe 时长写入歌曲轴 JSON；之后文件改变，`build` 会拒绝旧绑定，需要重新检查并重新初始化/迁移。

```sh
python3 "$SKILL_DIR/scripts/axis.py" init --media "$FINAL_MEDIA" --output "$WORKSPACE/work/song-axis/axis.json"
```

修改 `entries`，按媒体时间递增。示例是格式示范，不是该录播事实：

```json
{
  "start": 182.4,
  "title": "核对后的歌名",
  "artist": "已核对的歌手，未知可留空",
  "kind": "song",
  "confidence": "verified",
  "evidence": "复听 00:03:02 起唱及对应歌词；来源链接或本地证据路径",
  "note": "可选：尾段、串烧、重复演唱、含聊天"
}
```

`kind` 可用 song / chat / bgm / unknown；`confidence` 可用 verified / candidate / uncertain。verified 必须有 evidence，未确认的条目导出时显示“待核对”。时间可保留小数供剪辑使用，导航文本向下取整显示 HH:MM:SS；导航精度不能宣传为帧级切点。

## 从音频发现候选

1. 在最终视频提取 16 kHz 单声道 PCM16 WAV：`ffmpeg -nostdin -n -i 视频.mp4 -vn -ac 1 -ar 16000 -c:a pcm_s16le work/song-axis/audio.wav`。
2. 本地 Apple Silicon 可使用已安装的 `mlx_whisper` 与模型。脚本默认只接受现有本地模型目录；是否下载安装模型或使用外部转写服务按当前任务范围判断，不能悄悄把整场音频发给云服务。
3. 长视频按 600 秒分块转写，默认重叠 10 秒；逐块保存，避免失败重做整场：`python3 "$SKILL_DIR/scripts/transcribe.py" --audio audio.wav --model /实际/本地模型目录 --out-dir work/song-axis/transcripts`。
4. 结果是 ASR 证据，不是已确认歌曲轴。重叠块会保留重复候选，后续核对而非盲目当作两次演唱。使用 `--windows` 指向 `[[开始秒,结束秒], ...]` 可对疑似起唱、结束、口播和串烧边界做短窗口复核；放入单独的 out-dir 保留不同实验记录。

ASR 原始 `start/end` 相对于当前音频块；脚本只加一次窗口起点，并同时保存相对值用于追查。汇总 JSON 已经是全局时间，不要再加第二次。歌唱、伴奏、方言和口播可能混淆，识别到一句歌词不能证明歌名或原唱。

## 确认歌名与边界

- 先找歌词或明确报幕，再复听对应原视频附近，必要时查歌曲的官方发行/歌词来源。给预期歌名的提示词会污染识别，不以这种结果单独确认。
- 区分主播演唱、播放 BGM、聊天中随口哼唱和串烧。重复演唱保留两个时间位置，不按歌名去重。中途开始的第一首写“尾段/开头未录全”。
- 每个确定条目保留来源或人工复听窗口；不确定歌名留待核对。记录哪些边界人工听过、哪些只由 ASR 推定。仅做 ASR 和歌词检索时不能写“逐首完整听过”。
- 抽查第一项、中部项、重连/剪接边界、最后一项，实际跳转看起唱位置。短导航与纯歌曲切片分别校准；纯歌曲剪辑还必须核对结束点。

## 拼接、裁剪和多 P 换算

原片第 i 段局部时间 t → 无裁剪拼接的预计时间：`sum(前面各段实际媒体时长) + t`。断流期间没有画面，不能把墙上时钟的缺口加进视频时间；拼接后在成片验证映射。

从源文件保留多个 `[a,b)` 区间时，源时间 t 落在第 i 个保留区间 → `sum(前面保留区间长度) + t - a_i`；删除区间内的条目删去或重新定位。调速、转场、插入片头需反映实际编辑结果，不能只套加法。

多 P 每个文件单独从 00:00:00 计时，条目携带 P 号；不要把单文件总时间轴直接贴到每个 P。为每个最终文件分别生成轴和验证。

## 导出与文案

```sh
python3 "$SKILL_DIR/scripts/axis.py" build --input "$WORKSPACE/work/song-axis/axis.json" --out-dir "$WORKSPACE/outputs/投稿准备"
```

导出 `歌曲轴.json`、`歌曲轴.txt`、LosslessCut v2 `歌曲导航.llc`。LLC 区间从一个导航点到下一个，**会包含间奏和聊天，不是已精剪单曲**；打开工程定位媒体文件后再校准，不能直接导出并称为纯单曲。这个格式在本地案例用于导航，当前版本应用的载入与导出效果仍应现场核对。

在简介放来源、录制日期和范围、歌曲导航、缺口或未确认说明。保留可粘贴文本和核对证据。评论歌曲轴只有用户要求时才发布，并先查已有评论/置顶，避免重复。
